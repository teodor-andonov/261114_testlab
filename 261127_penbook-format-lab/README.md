# Penbook Format Lab

Disposable, browser-only experiment. One vertical block document, three equivalent self-contained formats. JSON is authoritative in all formats. HTML contains an authoritative JSON source near the top, a standard editing comment, and a pre-rendered static HTML article with native data-URI images. It works without JavaScript. Repeated image references may repeat the data URI. The .penbook format is a standard ZIP with `document.json`, `preview.html`, `AGENTS.md` and `assets/<id>`. The preview uses relative asset URLs, so image bytes are not duplicated. External edits only need to update the authoritative JSON, leaving the generated preview and existing image payloads untouched. The app renders fresh previews from source on open and regenerates the on-disk static preview on save. Standalone HTML previews may be stale until saved again. Old .zip files and previous HTML exports remain readable. JSON format is unchanged. ZIP output uses STORE, with CRC-32; input also accepts DEFLATE (modern Chromium). The ZIP reader reads the central directory and requested entries using Blob slices. The app loads all referenced images before showing the editor. No persistent database, network calls or external dependencies.

Use the command palette (Ctrl/Cmd+K) to load small/large synthetic image fixtures, export all three files, open/edit them, measure median encode/source-read/full-read time and check round-trip integrity. The blind agent prompt is displayed in the app. Give each agent only one file and the identical prompt; capture real token counts externally. The demo comparison expects original image bytes generated by the same browser/encoder. Use the exact original exports for cross-machine byte comparisons.

Scope: Markdown subset (headings, paragraphs, emphasis, inline code and bullets), image blocks, vertical order, captions/alt text. No nested layouts, arbitrary HTML blocks, thumbnails, or production compatibility guarantees. ZIP64, encrypted archives and files over 256 MiB are out of scope. No actual filesystem write timings are claimed.
